# «Послесвечение» — план разработки

> Источник: `Poslesvechenie_koncepciya.pdf` (Genesis Hackathon, кейс ArtTech «Make the Invisible Visible»).
> Главный принцип: **мы не генерируем картинку, мы проектируем правила.** Каждое визуальное решение выводится из «паспорта дня» и объясняется пользователю.
>
> Дизайн: направление «Свет звезды», веб mobile-first — см. [DESIGN.md](DESIGN.md).

---

## 1. Что строим (MVP для демо)

Пользовательский путь одной записи:

1. **Ввод** — текст о дне + 1–N фото + песня (ссылка / название / свой файл).
2. **Анализ** — три независимых анализатора (текст, фото, музыка) → сырые признаки.
3. **Паспорт дня** — вектор из 8 осей + флаг внутреннего конфликта («светлая грусть»).
4. **Правила** — паспорт → веса художественных приёмов + визуальные параметры.
5. **Живая открытка** — генеративная сцена 4:5, 15–30 с, играет под фрагмент песни.
6. **Название дня + рукописная подпись** (подпись — только слова пользователя).
7. **Карточка «Почему так выглядит»** — человеческое объяснение каждого решения.
8. **Папка дня** → архив: «Год в цветах», лента, фильтры, «В этот день».

Вне MVP (stretch): экспорт MP4, озвучка облачным TTS, геолокация/погода, мобильное приложение, общие дневники.

## 2. Технологический стек (предложение)

| Слой | Выбор | Почему |
|---|---|---|
| Приложение | **Next.js (App Router) + TypeScript + Tailwind** | Один репозиторий для UI и серверных роутов (прокси к API, ключи не светятся в браузере) |
| Рендер открытки | **PixiJS v8 + собственные GLSL-фильтры** | Слои фото + шейдеры (мазки, цветовые поля, зерно, VHS) в реальном времени |
| Анализ текста | **Claude API, structured output (JSON Schema)** | Строго типизированные эмоции/события/детали, название дня |
| Поиск песни и превью | **Deezer API** (превью 30 с + BPM/gain), фолбэк **iTunes Search API** | Официальные 30-секундные фрагменты, без хранения трека |
| Анализ аудио | **Essentia.js** в Web Worker (BPM, лад, энергия, спектральный центроид); фолбэк — Meyda | Реальный анализ фрагмента, а не угадывание |
| Анализ фото | k-means в цветовом пространстве Lab (свой код), **exifr** для EXIF, опционально MediaPipe Face Detector | Палитра из реальных снимков, время съёмки, наличие лиц |
| Хранилище | **IndexedDB через Dexie** (local-first) | Приватность: дневник не уходит на сервер, кроме текста на анализ |
| Озвучка | Web Speech API (MVP) → облачный TTS (stretch) | Только синтезированные голоса, как требует концепция |
| Экспорт видео | `canvas.captureStream()` + `MediaRecorder` → WebM; MP4 через ffmpeg.wasm (stretch) | Работает целиком в браузере |

## 3. Архитектура

```
src/
  app/                     # страницы Next.js
    new/                   # ввод записи
    day/[id]/              # папка дня: открытка + «Почему так» + исходники
    archive/               # «Год в цветах», лента, фильтры, «В этот день»
    api/
      analyze-text/        # → Claude, возвращает TextFeatures
      music/search/        # прокси Deezer/iTunes (CORS + нормализация)
  lib/
    analyzers/
      text.ts              # схема TextFeatures + валидация
      photo.ts             # палитра, яркость, контраст, EXIF, лица
      music.ts             # обёртка над воркером Essentia + метаданные
    passport/
      axes.ts              # 8 осей, каждая = значение 0..1 + источники (для объяснения)
      build.ts             # features → Passport
      conflict.ts          # детектор внутреннего конфликта
    rules/
      styles.ts            # 8 художественных приёмов: функции активации от паспорта
      mixer.ts             # веса → нормализация → топ-2/3 смешивание
      visual-params.ts     # паспорт → палитра, ритм, амплитуда, композиция, свет, плёнка
    explain/
      explain.ts           # детерминированные шаблоны «потому что…» из атрибуций
    render/
      scene.ts             # сборка сцены PixiJS, таймлайн под BPM
      layers/              # рамка-паспарту, фото-отпечатки, дата-штамп, подпись, название
      filters/             # GLSL: impressionism, rothko, kandinsky, ukiyoe, film, collage, turner, popart, grain, vhs
    storage/db.ts          # Dexie: days, photos (blobs), passports, renders
  workers/audio.worker.ts
```

### Ключевые контракты

```ts
type Axis = { value: number; sources: { input: 'text'|'photo'|'music'; note: string; weight: number }[] };

type Passport = {
  valence: Axis;      // светлый ↔ тяжёлый   (текст + лад)
  energy: Axis;       // тихий ↔ насыщенный  (текст + громкость/энергия трека)
  tempo: Axis;        // BPM песни
  temperature: Axis;  // холод ↔ тепло       (цвета фото + сезон + погода)
  density: Axis;      // события, люди, кадры
  intimacy: Axis;     // наедине ↔ толпа
  timeOfDay: Axis;    // текст + EXIF
  era: Axis;          // год и жанр песни
  conflict?: { kind: 'bright-sadness' | string; strength: number };
  seed: number;       // детерминизм: один и тот же день всегда рисуется одинаково
};
```

**Правило объяснимости:** каждое число в паспорте и каждый вес приёма несёт `sources`. Карточка «Почему так выглядит» строится только из них шаблонами — без LLM, чтобы объяснение было честным и воспроизводимым.

## 4. Таблица правил (первая версия, будем тюнить)

| Ось | Визуальный параметр |
|---|---|
| Валентность | светлота, насыщенность, доля «воздуха» |
| Энергия | амплитуда движения, контраст |
| Темп | ритм смены кадров, пульсация зерна (синхронно с BPM) |
| Температура | сдвиг палитры (hue shift + white balance) |
| Плотность | одна сцена ↔ коллаж |
| Близость | крупность кадра, виньетка |
| Время суток | характер света: дымка / золотой час / ночной неон |
| Эпоха | тип плёнки: зерно 60-х / VHS 80-х / чистое цифровое |

| Приём | Активация (примерно) |
|---|---|
| Импрессионизм (Моне) | спокойно + тепло + медленно |
| Кандинский / конструктивизм | высокая энергия + быстрый темп + напряжение |
| Цветовые поля (Ротко) | минор + низкая энергия + одиночество |
| «Ма» / укиё-э | тишина + наедине + утро |
| Плёнка / ломография | друзья + лето + ностальгия + старая эпоха песни |
| Коллаж / дадаизм | высокая плотность + хаос |
| Вихревой свет (Тёрнер) | сильные эмоции, гроза, перелом |
| Поп-арт / Хокни | солнце + праздник + мажор + танцевальный темп |
| **Светлая грусть** (конфликт) | грустный текст + весёлая песня → тёплая палитра, медленный ритм, много пустоты |

Постоянные элементы (всегда): рамка-паспарту, дата моноширинным «штампом» слева сверху, название внизу, рукописная подпись, фото как отпечатки с мягким краем, плёночное зерно.

## 5. Этапы и задачи

### Этап 0 — Фундамент
- [ ] Next.js + TS + Tailwind, ESLint/Prettier, `.env.example`, `.gitignore`
- [ ] Dexie-схема, базовая навигация (Новая запись / День / Архив)
- [ ] 5–7 **демо-дней** (текст + фото + песня) — эталон для тюнинга правил и для питча

### Этап 1 — Анализаторы
- [ ] Текст: JSON Schema (эмоции, события, места, люди, погода, сезон, время суток, сенсорные детали, кандидаты в подпись — **дословные цитаты**, название 3–7 слов); проверка, что подпись — подстрока исходного текста
- [ ] Фото: доминирующие цвета (k-means/Lab), яркость, контраст, EXIF-время, лица (опц.)
- [ ] Музыка: поиск → превью 30 с → Essentia в воркере; фолбэк по жанру/году; загрузка своего файла

### Этап 2 — Паспорт и правила (ядро продукта)
- [ ] `build.ts`: признаки → 8 осей с атрибуциями
- [ ] Детектор конфликта «светлая грусть»
- [ ] Функции активации 8 приёмов + микшер весов
- [ ] Юнит-тесты на демо-днях: «осень + какао + Синатра» ≈ 70% импрессионизм / 30% плёнка; «ночь в офисе + электроника» → Кандинский, сине-серая палитра

### Этап 3 — Рендер открытки
- [ ] Постоянные слои (рамка, дата, название, подпись, отпечатки, зерно)
- [ ] GLSL-фильтры: начать с 4 самых контрастных — импрессионизм, Ротко, Кандинский, плёнка; затем остальные
- [ ] Смешивание фильтров по весам, таймлайн под BPM, синхронное воспроизведение превью
- [ ] Палитра = цвета фото, сдвинутые температурой/валентностью

### Этап 4 — Папка дня и «Почему так выглядит»
- [ ] Экран дня: открытка, карточка объяснения, паспорт (радар 8 осей), исходники, ссылка на песню
- [ ] Озвучка текста: голос по валентности × энергии, скорость от BPM

### Этап 5 — Архив
- [ ] «Год в цветах»: календарь, день = полоска своей палитры
- [ ] Лента открыток, фильтры по настроению/сезону, «В этот день»

### Этап 6 — Полировка и питч
- [ ] Экспорт WebM (MP4 — stretch)
- [ ] Онбординг, согласия (геолокация/погода/дата), формулировки «настроение записи, а не диагноз»
- [ ] Демо-сценарий: показать 5–7 разных дней рядом → цельная серия; раскрыть «Почему так» на одном

## 6. Риски и как закрываем

| Риск | Решение |
|---|---|
| CORS/лимиты Deezer, нет превью | серверный прокси; фолбэк iTunes; фолбэк по метаданным; свой файл |
| Essentia.js тяжёлая (WASM) | ленивая загрузка в воркере; фолбэк Meyda + BPM из Deezer |
| LLM выдумывает подпись | подпись выбирается только из дословных фрагментов текста, проверяется подстрокой |
| Шейдеры не успеваем | 4 приёма в MVP, остальные — как пресеты параметров существующих фильтров |
| Safari и MediaRecorder | экспорт помечаем как Chrome-first, просмотр работает везде |
| Приватность | local-first хранение; на сервер уходит только текст для анализа, без сохранения |
